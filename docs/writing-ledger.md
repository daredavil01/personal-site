# The Writing Ledger — Refreshing Blog Word-Count Data

The Writing Ledger (`/writing-ledger.html`) is a self-contained infographic of
every blog post published on Substack and WordPress: total words, monthly and
yearly trends, month/year-to-date, top posts, tag and length breakdowns.

It is **not** built by Vite from live data. It is a static page generated by two
scripts and committed to the repo, so refreshing it is a manual step you run
whenever you want the numbers to catch up.

## The Two Commands

Run them in this order — the second one reads the first one's output.

```bash
npm run blogs:wordcount
```

```bash
npm run blogs:infographic
```

Then commit the regenerated page and deploy as usual.

## What Each Step Does

| Step | Script | Reads | Writes |
|---|---|---|---|
| 1. Extract | `scripts/blog-word-counts.mjs` | Substack archive API, WordPress.com API, Supabase `blogs` table | `knowledge_base/blog-word-counts.json` |
| 2. Render | `scripts/build-blog-infographic.mjs` | that JSON + `scripts/infographic-template.html` | `public/writing-ledger.html` |

**Step 1 — `npm run blogs:wordcount`** pages through both public APIs, counts
words per post, and aggregates by month, year, platform, day of week, section,
tag and length. It is read-only: it never writes to Supabase. It touches the
`blogs` table only to mark which published posts the site already tracks, using
the public publishable key under the table's "public read" RLS policy — so
**no `SUPABASE_SERVICE_ROLE_KEY` is needed**. If Supabase is unreachable the run
still succeeds and every post is marked `trackedInBlogsTable: null`.

**Step 2 — `npm run blogs:infographic`** inlines that JSON into the HTML
template at its `__DATA__` marker. The result opens straight from disk — no
fetch, no server, no CORS. It lives in `public/`, which Vite copies verbatim
into `build/`, so it is served at `/writing-ledger.html` on Cloudflare Pages.
The dot in the filename makes `functions/_middleware.js` skip it, so the page
keeps its own `<head>` tags instead of getting the SPA's meta injected over it.

## Prerequisites

Nothing to configure. Both blog APIs are public and unauthenticated, and the
Supabase URL and publishable key are baked into the script as defaults. You only
need Node 20+ and a network connection.

To point the extractor at a different Supabase project, set `SUPABASE_URL` (or
`VITE_SUPABASE_URL`) and `VITE_SUPABASE_PUBLISHABLE_KEY` in `.env` — the script
has a small built-in `.env` loader, so no `--env-file` flag is required.

Both scripts are re-runnable and idempotent. Running them twice in a row simply
overwrites the same two files with the same numbers.

## What Gets Committed

- ✅ `public/writing-ledger.html` — **commit this.** It is the deployed page.
- ❌ `knowledge_base/blog-word-counts.json` — **gitignored** (all of
  `knowledge_base/` is). It is an intermediate artifact, regenerated on demand.

So a refresh shows up in `git status` as exactly one changed file. If nothing
changed, no new posts have been published since the last run.

## Reading the Console Output

Step 1 prints a summary before it exits:

- **By year / By platform** — post and word totals per bucket. Note the
  `method` column: Substack numbers come from Substack's own `wordcount` field
  (`substack_api`), WordPress numbers are derived by stripping tags from the
  post body and splitting on whitespace (`derived_html`). The two are **not the
  same methodology**, so cross-platform comparisons are approximate.
- **To date** — month-to-date and year-to-date, each with a percentage change.
  The YTD comparison is cut at the same month/day last year, which is the only
  fair year-over-year read. Posts are bucketed in IST, matching how the site
  renders dates elsewhere.
- **Anomalies** — problems found, never fixed. This script does not write:

| Anomaly | Meaning | What to do |
|---|---|---|
| `untracked_post` | Published on Substack/WordPress but has no row in the Supabase `blogs` table | Add it via `/admin` → **100 Days (Blogs)** if it belongs there. A high count is normal — not every post is part of a tracked challenge. |
| `unmatched_blogs_row` | A `blogs` row whose `blog_link` matches no live post | Check the URL for a typo, or the post was unpublished |
| `malformed_blog_date` | A `blogs` row's `blog_date` is not `YYYY-MM-DD` | Fix it in `/admin` — it breaks month bucketing in the site's blog charts |
| `missing_word_count` | Substack returned no `wordcount` for a post | Usually a non-article post type; safe to ignore |

## Verifying the Result

Open `public/writing-ledger.html` directly in a browser (it needs no server).
The headline number and the "as of" date at the top should reflect today's run.

## Troubleshooting

**`Missing knowledge_base/blog-word-counts.json`** — you ran step 2 without step
1. Run `npm run blogs:wordcount` first.

**`Template has no __DATA__ marker`** — `scripts/infographic-template.html` was
edited and the placeholder was removed. Restore the `__DATA__` marker inside the
template's data `<script>` block.

**`Word-count extraction failed: 4xx/5xx`** — one of the upstream APIs is down or
rate-limiting. The script writes nothing on failure, so the existing JSON and
page are left intact. Wait and re-run.

**`blogs table: unavailable`** — a warning, not an error. The run continues; only
the tracked/untracked annotations and the `blogs`-related anomalies are skipped.
